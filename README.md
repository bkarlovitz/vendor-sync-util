# vendor-sync-util

Vendor library source code into your project so coding agents can read it.

## What and why

Giving coding agents the source code of third party libraries, rather than just docs, makes them more effective at using those libraries.

This utility is an approach to specifying the libraries you want vendored in a config file and syncing them into a gitignored directory in your project.

## Build from SPEC

This `sync.ts` was produced by a coding agent from [SPEC.md](./SPEC.md). Edit the spec to your own requirements as needed.

## Quickstart

```bash
# In your project root:
cp /path/to/vendor-sync-util/sync.ts tools/vendor/sync.ts
cp /path/to/vendor-sync-util/vendor.config.example.json vendor.config.json
echo "repos/" >> .gitignore

# Edit vendor.config.json to list your libraries, then:
bun tools/vendor/sync.ts sync
```

## Config

`vendor.config.json` at the project root declares what to vendor:

```json
{
  "outDir": "repos",
  "entries": [
    {
      "package": "effect",
      "version": "3.10.4",
      "repo": "https://github.com/Effect-TS/effect.git",
      "ref": "effect@3.10.4",
      "dir": "effect"
    },
    {
      "package": "hono",
      "version": "4.6.3",
      "repo": "https://github.com/honojs/hono.git",
      "ref": "v4.6.3",
      "dir": "hono"
    }
  ]
}
```

| Field | Required | Description |
|---|---|---|
| `outDir` | yes | Directory where vendored repos live. Conventionally `"repos"`. |
| `entries[].package` | yes | The npm package name. Used for cross-referencing with `package.json`. |
| `entries[].version` | yes | The npm semver version this entry corresponds to. Informational. |
| `entries[].repo` | yes | Full git URL of the upstream repository. |
| `entries[].ref` | yes | Exact git ref to check out — tag, branch, or SHA. Passed to `git clone --branch`. |
| `entries[].dir` | yes | Subdirectory name under `outDir`. Usually matches `package`. |

## Commands

### `bun sync.ts sync`

Reconciles `repos/` against the config:

- Missing entries are cloned at their configured ref (`git clone --depth 1 --single-branch --no-tags --branch <ref>`).
- Entries already at the configured ref are left alone.
- Entries at the wrong ref are deleted and re-cloned.
- Directories under `outDir` not in the config are deleted as orphans.

Prints one line per entry and a summary like `Synced 2 entries (1 cloned, 1 skipped, 0 orphans removed)`.

### `bun sync.ts status`

Prints an aligned table:

```
effect@3.10.4  ref=effect@3.10.4  present=yes  matches=yes
hono@4.6.3     ref=v4.6.3         present=no
```

Orphan directories are listed at the bottom.

## Recommended project setup

The script does not modify your project config — set these up once:

**`.gitignore`**

```
repos/
```

**`tsconfig.json`**

```json
{
  "exclude": ["repos"]
}
```

**`.vscode/settings.json`**

```json
{
  "typescript.preferences.autoImportFileExcludePatterns": ["repos/**"],
  "javascript.preferences.autoImportFileExcludePatterns": ["repos/**"],
  "files.exclude": { "repos/**": true },
  "files.watcherExclude": { "repos/**": true },
  "search.exclude": { "repos/**": true }
}
```

**`package.json`** — add a `sync-vendors` script:

```json
{
  "scripts": {
    "sync-vendors": "bun tools/vendor/sync.ts sync"
  }
}
```

**`CLAUDE.md` / `AGENTS.md`** — point the agent at the vendored source:

```markdown
## Vendored library source

`repos/` contains shallow clones of external libraries this project uses, pinned to the versions in `package.json`. Read these when you need to understand how a library actually works — they're the authoritative reference. Do not edit anything under `repos/`; it's regenerated by `bun tools/vendor/sync.ts sync`.
```

## Limitations

- TypeScript / JavaScript projects only.
- Public GitHub repositories only.
- No version inference from `package.json` or lockfiles — the config is fully explicit.
- No sparse / partial vendoring of monorepo subdirectories.

See [SPEC.md](./SPEC.md) for the full design and out-of-scope list.
